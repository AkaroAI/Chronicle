# Chronicle v0.10.1.4 — Canon Engine Stabilization

## Structured character location
Character location is now a first-class database field (`CharacterEntity.currentLocation`) instead of relying only on prose inside Notes.

Database schema migrates from 5 -> 6.
Existing note-based location history remains compatible.
New/imported/approved movement writes the structured field directly and also mirrors `Currently at LOCATION.` into Notes for compatibility with the current World Explorer renderer.

## Relational movement
Chronicle can resolve movement through another character's approved location.

Example:
- Mira.currentLocation = Old Stone Aqueduct
- Player: `Kael goes back to Mira.`
- Proposal: `Kael -> Old Stone Aqueduct`

Relational intent takes priority over incidental historical location mentions in the same sentence.

## Canon supremacy
The storyteller is explicitly subordinate to resolved canon.
Approved state cannot be vetoed or reversed by character autonomy or storyteller preference.
Autonomy may affect feelings/dialogue/reaction inside the approved state.

## Story output validation
Before an assistant reply is saved to campaign history, Chronicle checks for:
- empty/broken responses
- pathological single-word repetition
- repeated phrase loops
- obvious movement contradictions against structured character locations

A failed response is regenerated once with a correction instruction.
If the retry still fails, it is NOT stored in campaign history and the user receives an error.

## Stable AI temperatures
The OpenAI-compatible provider now accepts per-request temperature.
- continuity/canon analyzer: 0.15
- external import extraction: 0.20
- storyteller: 0.75

This reduces extraction variability while preserving creativity in roleplay.

## Turn-state reliability
The canon-first flow now tracks explicit phases internally:
IDLE -> ANALYZING_CANON -> AWAITING_REVIEW -> APPLYING_CANON -> GENERATING_STORY -> VALIDATING_STORY -> IDLE

Attempting to send a new story action while the current turn is waiting for Review now produces a clear notice instead of silently doing nothing.

## Import presence
External import still uses AI extraction plus deterministic location recovery.
Character presence is strengthened with a latest located Timeline-event fallback when direct source matching cannot resolve a location.
When imported character notes establish `Currently at LOCATION.`, import commits that into the new structured currentLocation field.

## Backups
Backup format is now v4 so structured character location survives export/import.
v4 continues to read older Chronicle backup versions.
