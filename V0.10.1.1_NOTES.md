# Chronicle v0.10.1.1 — Character Presence Fix

## What was broken
v0.10.1 instructed the AI analyzer to track character movement, but did not provide a deterministic movement fast-path.
If the analyzer skipped the movement, no character-update proposal was created and the map had no canonical location data to display.

## Fix
Normal chat now runs an explicit character-movement detector before the general AI continuity analyzer.

For clauses such as:
- `Asira and Yuki travel to Moonfall Academy.`
- `Lyra stays behind in Frostmere.`

Chronicle matches known canonical character names + known canonical locations and creates Character Update proposals using:
`Currently at LOCATION_NAME.`

The general AI analyzer still runs afterward as a safety net.

## Duplicate protection
If the same character/location proposal is already pending, the fast-path does not create another one.

## Latest-location rule
Character notes may contain historical location statements after many moves.
World Explorer now reads ONLY the latest `Currently at ...` statement for each character.

This prevents:
`Currently at Frostmere. Currently at Moonfall Academy.`
from showing the same character at both nodes.
