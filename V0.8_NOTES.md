# Chronicle v0.8.0 — Character Integrity Guard

## Integrity modes
Each character now has:
- Strict
- Balanced
- Flexible

Strict strongly protects identity-defining fields.
Balanced protects foundational identity while allowing normal development.
Flexible uses minimal automatic protection.

Additional fields can be manually protected per character from Review > Character Integrity.

## Protected-field approval
When a proposal touches protected core fields:
- normal one-tap approval is replaced by Review Override
- Chronicle shows the protected fields
- the user must explicitly confirm the override

The repository enforces this rule; it is not only a UI warning.

## Change modes
Reviewed character changes can use:
- Append — adds development without erasing prior canon
- Replace — replaces the stored value
- Clear — removes the field

This prevents every character-development proposal from being treated as a destructive rewrite.

## Evidence classification
Review can classify a change as:
- Player Confirmed
- Story Event
- Assistant Only
- Unverified

Assistant-only narration is blocked from rewriting identity-defining character fields.
Assistant-only narration is also blocked from becoming campaign-state or memory canon unless reclassified after review.

## Imported campaigns
External-imported Main characters start in Strict integrity mode.
Other imported characters start Balanced.

## Backups
`.chronicle` backup format is now v2 and preserves:
- integrity mode
- manual protected fields
- proposal change mode
- proposal evidence type
- integrity warnings

The importer remains backward compatible with v1 backups.

## Database
Room schema version: 4
Migration 3 -> 4 preserves all existing campaigns and defaults existing characters to Balanced protection.
