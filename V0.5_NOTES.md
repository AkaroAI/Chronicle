# Chronicle v0.5 — Review Inbox + Cast Importance

## Character cast tiers

Every character now has a separate cast tier:

- Main
- Secondary
- Supporting
- Background

The permanent numeric character ID remains unchanged and has no narrative meaning.

Existing v0.4 characters migrate to **Supporting** by default so nothing is silently promoted to Main cast.

## Background Impact Gate

Background characters do not generate ordinary character-sheet proposals.

A background `character_update` is accepted into Review only when the analyzer marks it:
- Critical, or
- High

The analyzer is instructed to route important consequences caused by background characters into World, Event, Lore, Relationship, or Quest folders instead.

Example:
- Background innkeeper likes apples → ignored.
- Background innkeeper poisons a Main character → Event / High proposal allowed.
- Background guard starts a civil war → World/Event / Critical proposal allowed.

## Proposal priorities

- Critical
- High
- Normal
- Low

The database and Review Inbox sort Critical first.

## Review folders

Pending proposals are grouped into:
- Characters
- World
- Events
- Relationships
- Lore
- Quests
- Other

Character proposals are then grouped by character.

Other groups use an AI-supplied folder label such as a location, arc, faction, quest, or relationship.

## Superseding

When a newer pending proposal targets the same entity and the same field as an older pending proposal, the older proposal becomes `Superseded` and disappears from the active inbox.

Example:
- Aldric injuries → "splinted broken leg"
- later Aldric injuries → "fully healed"
- the older splint proposal is superseded automatically.

No superseded proposal is ever applied to canon.

## Bulk actions

Folders containing multiple proposals provide:
- Approve all
- Reject all

Individual Approve / Edit / Reject remain available.

## Cast promotion

The continuity analyzer can propose:
`Supporting -> Secondary`
or similar changes when a character's repeated story impact clearly changes.

Cast-tier changes still require user approval.

## Update installation

v0.5 keeps the same package ID and uses the stable signing workflow established by v0.4.1.
It should install over v0.4.1 without uninstalling and preserve the existing local database and provider settings.
