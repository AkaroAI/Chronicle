# Chronicle v0.9.2 — Automation Safety Net

## Why this patch exists
v0.9.1 successfully automated world scanning, but testing revealed an existing quest could be missed by the automatic scan even though manual `Scan last exchange` found the completion immediately.

The root weakness was that automatic analysis could depend on UI StateFlow snapshots instead of a guaranteed fresh database snapshot.

## Fresh canonical snapshot
Every automatic continuity scan now reads a fresh canonical snapshot directly from Room immediately before analysis.

The snapshot includes:
- campaign state
- canonical characters
- memories
- locations
- factions
- quests
- timeline events

Manual `Scan last exchange` uses the same fresh database snapshot, so automatic and manual scanning now share the same source of truth.

## Automation coverage guard
Before returning no proposals, the analyzer is explicitly required to check every latest exchange for:
1. existing character changes
2. new canonical characters
3. location changes/discovery/status
4. faction changes
5. existing quest lifecycle changes
6. new quests/story threads
7. campaign location/objective changes
8. meaningful timeline milestones
9. durable memory/lore/relationship facts

## Quest lifecycle hardening
For an existing quest, Chronicle is instructed to reuse the EXACT stored quest title.
Lifecycle transitions:
- Active
- Paused
- Completed
- Failed

A completed/failed quest remains historical canon instead of being deleted.
Meaningful outcomes may separately produce a Timeline event.

## Canonical no-op suppression
Automatic scanning now suppresses world proposals that do not actually change canonical data:
- Locations
- Factions
- Quests
- Timeline events

This works in addition to v0.9.1's pending-proposal dedupe.
