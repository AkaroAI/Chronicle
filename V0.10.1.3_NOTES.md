# Chronicle v0.10.1.3 — Canon-First Turn Pipeline

## Core architecture change
Chronicle no longer lets the storyteller narrate ahead of Review.

New turn flow:
1. Player message is stored.
2. Deterministic quest + character movement detectors run.
3. AI canon analyzer runs against the player message BEFORE story generation.
4. If this turn created Review proposals, Chat pauses.
5. Player approves/rejects/edits those proposals in Review.
6. When every proposal belonging to that turn is resolved, Chronicle rebuilds a FRESH canonical database snapshot.
7. Only then does the storyteller generate the response.

If a turn produces no proposals, storytelling remains immediate.

## Why
This prevents Chat from narrating a state that the player later rejects or edits in Review.

## Pending-turn ownership
Only proposals created by the current turn block that turn.
Older unrelated Review items do not prevent normal story continuation.

## Fresh canon after Review
The resumed storyteller reads directly from the database after approval/rejection rather than using stale pre-Review StateFlows.

## Import character presence
External campaign analysis now explicitly asks for each character's last established current location.
A deterministic post-pass also searches the imported source against recognized canonical locations and appends:
`Currently at LOCATION_NAME.`
when a character's last explicit location can be recovered.

Unknown character positions remain unknown rather than being guessed.

## Chat approval behavior
Chat is not Review. The storyteller receives only resolved canon and is forbidden from creating an approval workflow inside narration.
